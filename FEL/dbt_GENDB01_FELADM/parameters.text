==============================================================================
DATE PARAMETERS THAT STILL NEED THE JOB_CONTROL FRAMEWORK
==============================================================================

Every Informatica mapping under FEL/Executed_sqls/ that carried a date or
time session parameter had that parameter resolved to a literal before the
script was validated, and the dbt models copy those literals verbatim.
They are therefore FROZEN: each model reloads the same window on every run.

This file lists what has to be swapped for a job-control lookup.

Nothing here is a defect in the conversion - the models reproduce the
validated script exactly, which is what the conversion was asked to do. The
remaining work is to replace each literal with the run window the framework
supplies.

Models: 47.  Models carrying a frozen window: 22.

------------------------------------------------------------------------------
SECTION B - CONSTANTS, NOT PARAMETERS
------------------------------------------------------------------------------
These were session variables in the validated script and are inlined in the
models. They are literals, not windows, and need no framework:

  $V_SESSSTARTTIME  -> CAST(CURRENT_TIMESTAMP() AS TIMESTAMP_NTZ)
                       Informatica SESSSTARTTIME, one value per session. The
                       model materialises it once into LAST_UPDT_TS and both
                       hooks read that column, so every row of a run still
                       carries the same stamp.
  $V_COMTRAC        -> 'COMTRAC'      system dimension name
  $V_REC_STATUS     -> 'ACTIVE'       feeder record status
  $V_RUN_STATUS     -> 'C'            ComTrac run status; the predicate
                       becomes the tautology 'C' = 'C' and is kept as
                       authored rather than removed.
  $V_BUSINESSENTITY -> 'BUSINESSENTITY'   FEL_DATATYPE_DIM lookup key
  $V_FACILITY       -> 'FACILITY'         FEL_DATATYPE_DIM lookup key
  $V_GEN_UNIT       -> 'GEN_UNIT'         FEL_DATATYPE_DIM lookup key
  $V_INVTRYLOC      -> 'INVTRYLOC'        FEL_DATATYPE_DIM lookup key

  The four FEL_DATATYPE_DIM keys were never echoed in any session log, so
  the literals are the names as they appear in the mapping. Confirm them
  against FEL_DATATYPE_DIM.DATA_TYPE_NM before the first production run.


------------------------------------------------------------------------------
SECTION C - HOW TO MAKE THE SWAP
------------------------------------------------------------------------------
The scaffolding is already in the project but deliberately not wired, so
that today every model reproduces its validated script exactly:

  seeds/FEL_JOB_CONTROL_SEEDS.csv    one row per Section A model (22)
  models/METADATA/FEL_JOB_CONTROL.sql  merges the seed into the control table
  macros/open_control_window.sql     opens the window in a pre-hook
  macros/update_control_table.sql    rolls the window in a post-hook

For each model in Section A:

  1. put the real Autosys job name in the seed, replacing TBD_<MODEL>, and
     in log_model_start / log_model_end in that model.
  2. add under the config block:
         -- depends_on: {{ ref('FEL_JOB_CONTROL') }}
  3. add to pre_hook, after log_model_start:
         open_control_window(this, '<AUTOSYS_JOB_NAME>')
     and to post_hook, before log_model_end:
         update_control_table(this, '<AUTOSYS_JOB_NAME>')
  4. add a JOB_CONTROL CTE at the top of the model body:
         WITH JOB_CONTROL AS (
             SELECT JOB_ID, START_DATE, END_DATE
             FROM {{ source('GENDB01_METADATA','FEL_JOB_CONTROL') }}
             WHERE JOB_NAME = '<MODEL>'
               AND AUTOSYS_JOB_NAME = '<AUTOSYS_JOB_NAME>'
         ),
  5. replace the frozen literal in the filter:
         <col> >  (SELECT START_DATE FROM JOB_CONTROL)
         <col> <= (SELECT END_DATE   FROM JOB_CONTROL)

ENFORCEMENT
-----------
log_model_start calls assert_ready_for_promotion, which raises a compiler error
on the qa, uat and prod targets if a frozen date literal is still in the model
body, or if the Autosys job name still starts with TBD. dev and ci are left
alone. So a model in Section A cannot be promoted until its window is real:
`dbt compile --target qa` fails with the model name and a pointer to this file.

The name used in open_control_window, update_control_table,
log_model_start, log_model_end, the JOB_CONTROL CTE and the seed must all
be the same string. If any one of them disagrees the UPDATE matches no row,
the window never advances, and nothing raises an error.
